# Журнал изменений для обновляющего агента

Новые версии сверху. У каждой версии — раздел «Как обновить приложение»: шаги, которые агент выполняет в приложении, подключившем набор `@ykurilov/remontnik-*`.

## 0.1.2

Исправление `check-config`.

- **Закрытая папка сценариев рядом со сценариями.** Если отложенные сценарии лежат в соседней закрытой папке (например, `closedPaths: ["evals/scenarios-holdout/**"]`, а `scenariosDir` — `evals/scenarios`), `check-config` больше не пишет ложную ошибку «закрытый путь похож на сценарии eval, но лежит вне scenariosDir». Это законное устройство: врач запускает только сценарии из `scenariosDir`, названные в `evalScope`. Ошибка остаётся для настоящей опасности: сценарий из `evalScope` лежит под закрытым путём вне `scenariosDir`, и врач его запустит. Предупреждение «папки сценариев нет» не изменилось.

### Как обновить приложение

1. Поднять `@ykurilov/remontnik-watch` и `@ykurilov/remontnik-core` до `0.1.2` точными версиями. На сервере перевести клон Ремонтника на метку `v0.1.2` и пересобрать врача (`docker compose -f deploy/compose.remontnik.yml up -d --build`).
2. Больше ничего менять не нужно. Если раньше из-за ложной ошибки закрытую папку сценариев переносили или переименовывали, можно вернуть прежнее устройство.
3. Проверить внутри контейнера врача (`docker compose -f deploy/compose.remontnik.yml exec doctor remontnik-doctor check-config`): ложной ошибки про закрытый путь сценариев нет.

## 0.1.1

Исправления по первому подключению.

- **Папка сценариев eval.** Врач считал, что сценарии лежат в `eval/scenarios`. Если у приложения они в другой папке, закрытые пути (`closedPaths`) сценариев не срабатывали, и врач мог запустить закрытый сценарий. Теперь папка задаётся в `checks.eval.scenariosDir` (по умолчанию `eval/scenarios`). `check-config` предупреждает, если папки нет, и пишет ошибку, если закрытый путь сценариев лежит вне неё.
- **Хуки сторожа и Agent Chat SDK.** `agentChatWatchHooks(...)` теперь подставляется в `createChatService` и `createChatHandler` без приведения типов (раньше — ошибка TS2345 «Index signature is missing»).
- **`check-config` не в контейнере врача.** Запуск на хосте из `node_modules` приложения раньше давал «Cannot find package '@ykurilov/remontnik-core'». Теперь `check-config` прямо пишет, что запущен не из контейнера врача, и даёт команду: `docker compose -f deploy/compose.remontnik.yml exec doctor remontnik-doctor check-config`.
- **Документы.** `extraOrigins` — поле политики браузера (`browser-policy.json`, путь в `REMONTNIK_BROWSER_POLICY`), а не `remontnik.config.ts`. В `docs/configuration.md` и `docs/getting-started.md` (шаг 12) теперь сказано, что где задаётся.

### Как обновить приложение

1. Поднять `@ykurilov/remontnik-watch` и `@ykurilov/remontnik-core` до `0.1.1` точными версиями. На сервере перевести клон Ремонтника на метку `v0.1.1` и пересобрать врача (`docker compose -f deploy/compose.remontnik.yml up -d --build`).
2. Сценарии eval лежат не в `eval/scenarios` — вписать их папку в `checks.eval.scenariosDir` в `remontnik.config.ts`. Проверить, что закрытые пути сценариев начинаются с этой папки.
3. Если хуки сторожа приводились к типу SDK (`as unknown as ...`) — убрать приведение. `pnpm typecheck` приложения должен остаться зелёным.
4. Если `extraOrigins` по ошибке вписан в `remontnik.config.ts`, перенести его в политику браузера на сервере.
5. Проверить внутри контейнера врача (`docker compose -f deploy/compose.remontnik.yml exec doctor remontnik-doctor check-config`, не с хоста): `check-config` пишет «ошибок нет» и не предупреждает о папке сценариев.

## 0.1.0

Первый выпуск. Обновлять нечего: приложение подключается впервые.

### Что умеет набор

- **Сторож** (`@ykurilov/remontnik-watch`) живёт внутри приложения. Ловит падения, ошибки модели и инструментов, при желании — плохие ответы бота. Каждый сбой — одно сообщение в Telegram и одна запись случая; повтор увеличивает счётчик.
- **Врач** (`@ykurilov/remontnik-doctor`) работает отдельным контейнером на сервере приложения. Находит причину, правит код в отдельной ветке, проверяет тестами и eval. Выкатывает сам только при зелёных проверках, потом следит за приложением и откатывает, если стало хуже.
- **Границы.** Врач не трогает запретные зоны (схема базы, деньги, доступы) и существующие тесты. Есть потолки по деньгам и числу попыток; после них врач пишет «нужен человек». Упал сам врач — продолжит с места.
- **Браузер врача** (`@ykurilov/remontnik-browser`) — по желанию: повторить ошибку глазами пользователя.
  Пароль модель не видит. С первого вписанного пароля и до конца сеанса профиля браузер ходит только на адреса из `allowedOrigins`. Картинки, шрифты и CDN с других сайтов открывает поле `extraOrigins` (только подресурсы). Политику проверяет `remontnik-browser check-policy`, у врача — `check-config`.
- **Режим «сначала Paseo»** (`@ykurilov/remontnik-paseo-bridge`) — по желанию: случай сперва получает агент проекта, врач берёт его сам, если агент недоступен или замолчал.
- Код приложения Ремонтник не правит: подключение делает агент приложения в его репозитории и на его сервере.

### Как подключить

Полная пошаговая инструкция — [docs/getting-started.md](./docs/getting-started.md). Каждый шаг там кончается проверкой. Коротко:

1. Спросить владельца только то, чего нет в коде: репозиторий и основная ветка, сервер и ручная выкатка, чат и бот Telegram, нужны ли браузер и режим «сначала Paseo».
2. Поставить `@ykurilov/remontnik-watch` и `@ykurilov/remontnik-core` точными версиями. Врача в приложение не ставить.
3. Подключить сторожа в каждый процесс приложения (`createWatch`).
4. Написать `remontnik.config.ts` в корне: запретные зоны, где врач может править, команды проверки.
5. Дать команды выкатки `build`, `promote`, `confirm`, `rollback`, `current`, `health`. `promote` выходит, только когда кандидат уже отвечает. Адреса команды берут из своих файлов на сервере: переменные с `URL` в имени врач им не передаёт. Проверить вручную: `build` → `promote` → `rollback`.
6. По желанию — eval и службы для тестов.
7. Задать окружение сервера; секреты — только через `secret-handoff`.
8. Запустить врача контейнером из `deploy/compose.remontnik.yml`.
9. Проверить: `remontnik-doctor check-config` пишет «ошибок нет».
10. Включить правила GitHub и стоп-кран; по желанию — браузер врача и режим «сначала Paseo».
11. Прогнать тестовый сбой: он доходит до врача и в Telegram, ручной `rollback` возвращает прежнюю версию.
