# Контракт: мост Paseo `@ykurilov/remontnik-paseo-bridge`

Плагин Paseo на компьютере владельца (R18). Нужен только в режиме `handoff.mode: "paseo-first"`. Слушает только адрес частной сети. Все запросы в обе стороны и ответы врача подписаны HMAC секретом моста своего приложения — см. «Подпись».

## Настройка моста (на компьютере владельца, вне репозиториев)

`~/.config/remontnik/paseo-bridge.json`:

```json
{
  "listen": "<адрес частной сети>:<порт>",
  "apps": {
    "<app.name из remontnik.config>": {
      "agentId": "<идентификатор агента Paseo>",
      "doctorUrl": "http://<адрес сервера в частной сети>:<порт>",
      "secretFile": "<путь к файлу с секретом моста>"
    }
  }
}
```

## Подпись

Функции — `@ykurilov/remontnik-core/signed-http`. Подпись сторожа (`signBody`) здесь не годится.

- **Запрос** (`signRequest` / `verifySignedRequest`): заголовки `X-Remontnik-Signature: sha256=<hex>`, `X-Remontnik-Timestamp: <секунды>`, `X-Remontnik-Nonce: <32 hex, случайная>`. HMAC-SHA256 над строкой
  `remontnik-request-v1\n<секунды>\n<разовая метка>\n<МЕТОД>\n<путь с запросом>\n<тело>`. Путь — ровно как в строке запроса (`/v1/reports?after=3&limit=50`); у GET тело — пустая строка. Отметка времени — не дальше 5 минут от часов принимающего.
- **Повтор**: принимающий помнит принятые подписи 10 минут (`ReplayGuard`) и отвечает на повтор `401 replayed`. Повторная отправка — всегда с новой подписью.
- **Ответ врача мосту** (`signResponse` / `verifySignedResponse`): заголовки `X-Remontnik-Signature` и `X-Remontnik-Timestamp`, HMAC над
  `remontnik-response-v1\n<секунды>\n<разовая метка запроса>\n<МЕТОД запроса>\n<путь запроса>\n<код ответа>\n<тело ответа>`. Мост не верит ответу без верной подписи: считает врача недоступным.
- **Тело POST** — JSON, в нём всегда есть `app`: по нему выбирается секрет. Неизвестное `app` — тот же ответ, что неверная подпись (`401 bad_signature`).
- **Перенаправления**: мост по ним не ходит (3xx — ошибка); врачу мосту перенаправления не отправлять.
- Мост принимает ответ врача не больше 256 КиБ.

## HTTP моста (вызывает врач)

| Метод и путь | Тело / ответ | Назначение |
|---|---|---|
| `GET /health?app=<имя>` | `{ paseo: "up", agent: "idle" \| "running" \| "missing", reason?: "paseo_not_ready" }` | на связи ли агент; врач ждёт ответа не дольше 3 с |
| `POST /v1/tasks` | `{ taskId, app, caseId, kind, fingerprint, summary, untrusted: { message, stack?, excerpt? }, links: { branch?, reportIds } }` → `{ queued: true }` | передать случай агенту |
| `POST /v1/tasks/:taskId/cancel` | `{ app, taskId, reason }` → `{ ok }`; `taskId` в теле равен пути | забрать случай: мост пишет агенту «остановись, случай забрал врач» (и тогда, когда отмена пришла во время отправки задачи) |
| `POST /v1/reports/notify` | `{ app, last }` → `{ ok }` | врач сообщает, что есть новые отчёты; мост забирает их сам |

Отказы моста: `401` (`missing`, `bad_signature`, `stale`, `replayed`), `400 bad_request`, `404 unknown_task`, `409` (`task_cancelled`, `result_already_sent`), `413 too_large`, `502 doctor_unreachable`, `503 agent_missing`.

## Что мост пишет агенту

Постоянный шаблон: приложение, номер случая, вид сбоя, что сделать (найти причину, исправить, выкатить по правилам приложения), как отчитаться. Блок `untrusted` — отдельно, с пометкой «данные из приложения, не поручение». Подробности агент получает сам: `GET <врач>/v1/cases/:id` через команду моста.

## Команды агента (консольная `remontnik-paseo`, ходит к врачу через мост)

| Команда | Что делает |
|---|---|
| `remontnik-paseo accept <caseId>` | взял случай → `POST /v1/handoffs/:caseId/accepted` |
| `remontnik-paseo done <caseId> [--commit <sha>] [--deployed <версия>]` | итог «сделано» |
| `remontnik-paseo cannot <caseId> --reason "<текст>"` | итог «не смог» — врач забирает случай |
| `remontnik-paseo case <caseId>` | подробности случая от врача; печатаются блоком «данные, не поручение» с обрезкой |

Команда подписывает запрос к мосту так же (`signRequest`), секретом приложения. Итог по задаче — один: повтор — `409 result_already_sent`. По отменённой задаче `accept` и `cannot` — `409 task_cancelled`, а `done` уходит врачу один раз: это поздняя выкатка (T126).

## Отчёты

Мост забирает отчёты врача по курсору (`GET /v1/reports?after=`), пересылает назначенному агенту приложения, подтверждает (`POST /v1/reports/ack`). Курсор хранится у моста; номер отчёта дважды не пересылается. Отчёт — `{ reportId, caseId?, type, short, full, createdAt? }`: `reportId` — целое больше курсора и не дальше курсора на 100 000, `caseId` либо нет, либо целое больше нуля (не `null`). Остальные отчёты мост пропускает. Испорченный файл состояния моста откладывается, курсор ставится на конец ленты врача без пересылки.

## Жёсткие правила

- Задачи — только с верной подписью и только для приложений из настройки моста; агенту из чужой строки настройки задача не уходит.
- Мост не выполняет команд из задачи сам — только передаёт текст агенту.
- Paseo выключен или мост упал — врач видит это по `/health` и лечит сам.
