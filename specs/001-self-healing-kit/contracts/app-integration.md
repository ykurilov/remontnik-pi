# Контракт: что делает приложение при подключении

Подключение делает агент приложения по `docs/getting-started.md`. Ремонтник код приложения не правит. Список ниже — то, что приложение обязано дать.

1. **Сторож в коде**: `createWatch` при старте каждого процесса; `installProcessHandlers()`; хуки `/agent-chat`, если стоит Agent Chat SDK; `conversationFinished` в месте, где разговор закрывается; `watch.flush` при штатной остановке.
2. **Файл `remontnik.config.ts`** в корне, с запретными зонами, закрытыми путями, картой eval и командами.
3. **Команды выкатки** по [deploy-commands.md](./deploy-commands.md): `build` из указанной папки, `promote` с сохранением прежней сборки, `rollback` без git, `current` с версией, `health`. Общий файл-замок с ручной выкаткой.
4. **Команда eval** с выбором сценариев, потолком денег и итогом в формате контракта; отдельные ключи моделей для eval с маленьким лимитом; отдельная база для прогонов.
5. **Службы для тестов** (если тестам нужна база) — файл compose, который врач может поднять отдельно от боевых.
6. **Окружение сервера**: общий секрет сторожа и врача, ключ git врача, ключи моделей Ремонтника, токен бота тревог, ключи браузера — по `secret-handoff`, только в окружении сервера.
7. **Правила GitHub** из `deploy/github-ruleset.json`.
8. **Учётка Ремонтника** в кабинете приложения и сохранённый вход в браузере (открытые вопросы 5, 6).
9. **Конституция и правила приложения** не должны запрещать автоматическую выкатку врачом (открытый вопрос 2).
10. **Стоп-кран в Telegram** — передача нажатия кнопки врачу (открытый вопрос 8).

Для Генератора лидмагнитов конкретные пути, маски и недостающие части собраны в частном файле `.private/lead-magnet-integration.md` (вне git) и передаются агенту приложения задачей.
