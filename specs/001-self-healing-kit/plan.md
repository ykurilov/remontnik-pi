# План реализации: Ремонтник Pi — набор самолечения приложения

**Ветка**: `main` (папка `specs/001-self-healing-kit`) | **Дата**: 2026-10-26 | **Спецификация**: [spec.md](./spec.md)

**Вход**: [spec.md](./spec.md), решения Юрия, [open-questions.md](./open-questions.md)

## Кратко

Пять пакетов `@ykurilov/remontnik-*` в одном pnpm-монорепозитории:

- **core** — общие типы, настройка приложения, вычистка секретов, отпечатки, путь к модели с запасным вариантом, Telegram, подпись запросов;
- **watch** — сторож внутри приложения: ловит сбои, очередь на диске, Telegram сразу, чтение законченных разговоров;
- **doctor** — врач на сервере на pi-durable 1.4.0: случаи, конвейер лечения (поиск причины → правка → проверки → решение → выкатка → наблюдение → откат или слияние), защита от циклов и трат, отчёты;
- **browser** — свой браузер на Playwright + Chromium: глаза врача, пароли модель не видит;
- **paseo-bridge** — по желанию: плагин Paseo на компьютере владельца. В режиме «сначала Paseo» врач отдаёт случай главному агенту приложения по частной сети и лечит сам, только если тот недоступен (R18).

Модель решает только поиск причины и правку, внутри изолированного контейнера-верстака. Решение о выкатке, выкатка, откат, git и проверки — обычный код с тестами. Весь цикл проверяется на учебном приложении «Пациент» без Docker и сети. Технические решения — в [research.md](./research.md).

## Технический контекст

**Язык и версия**: TypeScript 5.x (строгий режим), Node 22.19+ (требование pi-durable), ESM.

**Основные зависимости**: `@earendil-works/pi-durable` 1.4.0, `@earendil-works/pi-ai` 1.4.0, `@earendil-works/chord` 1.4.0 — точно, без диапазонов; `playwright-core` (закреплённая версия) + Chromium; `typebox` (схемы инструментов, как в pi-durable); `zod` для настройки. В `watch` и `core` — без тяжёлых зависимостей (только Node и `fetch`).

**Хранение**: врач — SQLite pi-durable (`node:sqlite`, один файл); сторож — файлы JSONL очереди; браузер — зашифрованный файл входов и папки профилей.

**Тесты**: vitest (юнит, интеграционные, падения), Playwright (браузер против «Пациента»), живая группа `test:live` (DeepSeek, Docker) отдельно.

**Платформа**: Linux-сервер приложения с Docker; разработка на macOS, прогоны на iMac.

**Тип проекта**: библиотека пакетов + две службы (врач, браузер) + учебное приложение.

**Цели по скорости**: сторож добавляет в горячий путь приложения не больше 1 мс на событие (синхронная дозапись строки); сообщение о сбое ≤ 1 мин; откат ≤ 1 мин.

**Ограничения**: открытый репозиторий без секретов и адресов; запретные зоны — кодом; один процесс врача на приложение; потолки расходов.

**Масштаб**: одно приложение — один врач; десятки случаев в сутки; сотни разговоров в сутки на чтение.

## Проверка конституции

*До исследования и повторно после дизайна.*

| Принцип | Как выполнен | Итог |
|---|---|---|
| I. Открытый репозиторий без секретов | `gitleaks` + `check-public` в `verify` и выпуске; частный запретный список вне репозитория; данные закрытого приложения — в `.private/` вне git; примеры на `example.com` | ✅ |
| II. Безопасность выкатки важнее скорости | `deploy-gate` — чистая функция с полным набором условий (R6); метка и прежняя сборка обязательны до `promote`; наблюдение и откат (R9) | ✅ |
| III. Запретные зоны неприкосновенны | встроенные запреты без выключения + маски приложения; настройка только из основной ветки (R7) | ✅ |
| IV. История неприкосновенна | `git-guard` + правила GitHub (R8); слияние — только обычный push, по настройке | ✅ |
| V. Без циклов и лишних трат | `FingerprintLedger`, `SpendLedger`, неизменный префикс промпта (R3) | ✅ |
| VI. Работает без Paseo | Telegram — всегда; отчёты в Paseo — мост забирает по курсору (R13); режим «сначала Paseo» — по желанию, при любом отказе Paseo врач лечит сам (R18) | ✅ |
| VII. Глубокие модули, тонкие интерфейсы | 5 пакетов; внутри врача — модули с узким интерфейсом (ниже) | ✅ |
| VIII. Сначала тесты | каждая задача модуля начинается с красного теста; модели подменены; живые — отдельной группой | ✅ |

Нарушений нет. После дизайна — без изменений.

## Как модули связаны

```text
Приложение ──(watch)──► Telegram (сразу)
     │
     └─ события (HMAC) ─► doctor/intake ─► case-book ─► treatment (pi-durable)
                                                      │
          ┌─────────────────────────────────────────────┤
          ▼                                             ▼
   model + workbench (модель правит в верстаке)    checks (оркестратор)
          │                                             │
          └──────────────► diff-inspector + forbidden-zones + ledgers
                                       │
                                  deploy-gate ──► report_only ─► reports
                                       │
                                     deploy ─► deployer (замок, метка, build, promote, health,
                                               наблюдение, confirm | rollback) ─► git-guard (слияние)
                                       │
                         browser-tools ◄┘ (по желанию: повтор ошибки, проверка страниц)

Режим «сначала Paseo» (по желанию):
case-book ─► handoff ─(частная сеть, HMAC)─► paseo-bridge ─► главный агент приложения
                ▲                                   │ чинит и выкатывает по правилам приложения
                └──── accepted / done / cannot ◄────┘
handoff: done + выкатка ─► deployer (наблюдение, откат) │ нет ответа / срок / cannot ─► treatment (врач сам)
```

## Риски

| Риск | Ответ |
|---|---|
| pi-durable ломает API между версиями | точная версия, обновление — отдельной задачей; узкий слой `doctor/service` + `doctor/treatment` — единственные места, где он используется |
| DeepSeek 4.1 Flash не находит причину сложных сбоев | потолок денег на поиск; отчёт «не нашёл» с выясненным; выкатка только при зелёных проверках, так что слабая правка не уйдёт |
| Правка модели крадёт ключи при eval или в работе | отдельные ключи eval с лимитом; `diff-inspector` останавливает новые обращения к окружению, внешним адресам, процессам (R6) |
| Шумные eval дают ложный «хуже» | сравнение с кэшированной основой; нестабильный = красный; это ведёт к отчёту, а не к плохой выкатке |
| Ручная выкатка совпала с выкаткой врача | общий файл-замок; смена `current` во время наблюдения → врач отходит в сторону |
| Утечка пароля браузера | семь замков (R12); остаток риска принят Юрием вместе с отдельной слабой учёткой |
| Живой экран — ещё одна дверь в браузер | только адрес частной сети, ключ владельца отдельно от ключа врача, кадры не идут модели (R12) |
| Чужая фраза в тексте ошибки становится поручением всесильному агенту на компьютере владельца | постоянный шаблон задачи, тексты приложения — блоком «данные, не поручение»; мост принимает только подписанное врачом и только для назначенного агента (R18) |
| Врач и агент Paseo правят один случай одновременно | один хозяин случая (`owner`), отмена перед тем, как врач берётся сам; общий замок выкатки (R18) |
| Плагин Paseo не может держать свой HTTP-адрес | проверка первой задачей этапа 11; при неудаче — остановиться и спросить Юрия |
