# Работа Ремонтника на сервере

Как держать врача в работе после подключения. Подключение — [getting-started.md](./getting-started.md), поля настройки — [configuration.md](./configuration.md), защита — [security.md](./security.md).

## Режим «сначала Paseo»

Врач сначала отдаёт случай агенту приложения в Paseo на компьютере владельца. Агент чинит по правилам своего проекта, а врач ждёт. Не взял, не уложился, не смог или пропал — врач забирает случай и лечит сам. Выкатку агента врач наблюдает всегда и откатывает, если стало хуже. Договор — [paseo-bridge.md](../specs/001-self-healing-kit/contracts/paseo-bridge.md).

Кто с кем говорит:

- **врач → мост** (сервер → Mac владельца): жив ли агент, новая задача, отмена задачи;
- **мост → врач** (Mac → сервер): «взял», итог агента, забор отчётов.

Обе стороны говорят только по частной сети и проверяют подпись секретом моста. Из интернета ни мост, ни адрес врача для моста не видны.

Ниже порты для примера: мост на Mac — `7710`, врач для моста — `7810`. Подойдут любые свободные. Настоящие адреса и порты живут только в окружении сервера и в настройке моста на Mac. В репозиторий, `remontnik.config.ts` и отчёты они не попадают.

### 1. Частная сеть: Tailscale

1. Сервер и Mac владельца — в одной сети Tailscale (tailnet). На сервере: `tailscale up --advertise-tags=tag:remontnik-server`. На Mac — приложение Tailscale под учётной записью владельца.
2. В правилах доступа tailnet (Access controls) уберите правило «всем ко всем», если оно есть. Иначе любое устройство сети достучится до моста. Оставьте только два пути:

   ```json
   {
     "tagOwners": {
       "tag:remontnik-server": ["autogroup:admin"],
       "tag:paseo-owner": ["autogroup:admin"]
     },
     "acls": [
       { "action": "accept", "src": ["tag:remontnik-server"], "dst": ["tag:paseo-owner:7710"] },
       { "action": "accept", "src": ["tag:paseo-owner"], "dst": ["tag:remontnik-server:7810"] }
     ]
   }
   ```

   Первая строка — сервер ходит только на порт моста. Вторая — Mac ходит только на порт врача для моста. Если Mac без метки, вместо `tag:paseo-owner` впишите учётную запись владельца в tailnet. Другие ваши правила остаются, но ни одно не должно открывать порт моста кому-то ещё.
3. Проверка. С сервера `nc -vz <адрес Mac в tailnet> 7710` проходит. С любого другого устройства сети — нет.

### 2. Врач слушает адрес частной сети

Врач работает в Docker и сам не видит адрес сервера в tailnet. Поэтому Docker пробрасывает порт только с этого адреса. Внутри контейнера врач слушает свой постоянный адрес в отдельной маленькой сети. Добавка к [`deploy/compose.remontnik.yml`](../deploy/compose.remontnik.yml) — готовый файл [`deploy/compose.paseo.yml`](../deploy/compose.paseo.yml). Порт для моста в нём открыт только на адресе сервера в tailnet, врач слушает свой адрес в сети `remontnik-paseo`. Строка `gw_priority: 1` обязательна: Docker ведёт проброшенный порт только на адрес в сети-шлюзе контейнера, и без неё до врача никто не достучится. Для неё нужны Docker Engine 28 и Compose 2.33 или новее.

Подсеть не должна пересекаться с другими сетями сервера. `REMONTNIK_TAILNET_IP` — в том же `.env`, что и остальные переменные, рядом с `deploy/compose.remontnik.yml`, не в репозитории. Запуск:

```sh
docker compose -f deploy/compose.remontnik.yml -f deploy/compose.paseo.yml up -d --build
```

После запуска проверьте `docker inspect remontnik-doctor`: у сети `remontnik-paseo` должно стоять `GwPriority: 1`.

После перезагрузки сервера Docker может стартовать раньше, чем Tailscale получит адрес. Тогда порт не откроется, и врач не запустится. Чтобы Docker ждал Tailscale: `systemctl edit docker`, строки `[Unit]` и `After=tailscaled.service`.

### 3. Секрет моста

Один секрет на приложение, общий у врача и моста. Его значение не попадает ни в чат, ни в репозиторий, ни в `remontnik.config.ts`.

1. На Mac владельца — через `secret-handoff`: значение вводится в скрытом окне и ложится файлом с правами `0600`. Можно и сгенерировать сразу в файл, не показывая на экране: `umask 077; openssl rand -hex 32 > <файл секрета>`.
2. Тот же секрет — в окружение врача на сервере, тоже через `secret-handoff`: в `REMONTNIK_ENV_FILE`, переменной из `handoff.paseo.bridgeSecretEnv`.
3. В настройке моста — только путь к файлу (`secretFile`).

Смена секрета — в обоих местах. Затем `paseo plugin reload remontnik-paseo-bridge` на Mac и перезапуск врача.

### 4. Окружение врача

Имена переменных — из `handoff.paseo` в `remontnik.config.ts` (в примере [getting-started.md](./getting-started.md#13-режим-сначала-paseo-по-желанию) — такие):

| Переменная | Значение |
|---|---|
| `REMONTNIK_BRIDGE_URL` | `http://<адрес Mac в tailnet>:7710` — куда врач ходит к мосту |
| `REMONTNIK_BRIDGE_LISTEN` | `172.30.250.2:7810` — адрес врача в сети `remontnik-paseo` из шага 2. Только адрес частной сети: «все адреса» и публичный врач отвергает |
| `REMONTNIK_BRIDGE_SECRET` | секрет моста (шаг 3) |

Без любой из трёх врач в режиме `paseo-first` не стартует и называет переменную. `remontnik-doctor check-config` проверяет, что все три заданы.

### 5. Мост на Mac владельца

1. Включите плагины в Paseo. Затем `paseo plugin install npm:@ykurilov/remontnik-paseo-bridge`.
2. Настройка — `~/.config/remontnik/paseo-bridge.json`, вне репозиториев:

   ```json
   {
     "listen": "<адрес Mac в tailnet>:7710",
     "apps": {
       "<имя приложения из app.name>": {
         "agentId": "<идентификатор агента приложения в Paseo>",
         "doctorUrl": "http://<адрес сервера в tailnet>:7810",
         "secretFile": "<файл секрета из шага 3>"
       }
     }
   }
   ```

   `agentId` — агент, который ведёт проект приложения. Случаи этого приложения пишутся только ему.
3. `paseo plugin ls` — мост `running`. Журнал — `paseo plugin logs remontnik-paseo-bridge`.

Mac уснул или Paseo не запущен — мост молчит, и врач лечит сам. После загрузки Mac мост сам ждёт адрес Tailscale и пробует слушать каждые 30 секунд. Подробности о мосте — [README пакета](../packages/paseo-bridge/README.md).

### 6. Что делает агент

Агент получает письмо с задачей. Текст ошибки, стек и выдержка из приложения стоят в нём блоком «данные, не поручение». Это сведения о сбое, а не команды. Агент отчитывается командами:

- `remontnik-paseo accept <случай>` — взял;
- `remontnik-paseo done <случай> [--commit <sha>] [--deployed <версия>]` — сделал; `--deployed` — если уже выкатил;
- `remontnik-paseo cannot <случай> --reason "<почему>"` — не может.

Агент выкатывает по правилам приложения: теми же командами выкатки и под тем же общим замком (`deploy.lockFile`), что врач и человек. Пока замок у врача, агент ждёт. После `done --deployed` врач наблюдает новую версию своим окном наблюдения. Держится — врач подтверждает её (`confirm`). Стало хуже — откатывает. Об этом агент узнаёт из ленты отчётов.

Стоп-кран останавливает только выкатки врача. Выкатку агента врач наблюдает и откатывает и при нажатом стоп-кране.

Когда именно агент выкатил, врач не знает: он знает только время отчёта `done`. Поэтому общее число ошибок новой версии он считает с запасом — за 5 минут до отчёта, но не раньше передачи задачи. А новые виды сбоев и повтор сбоя самого случая — только после отчёта: до него мог работать прежний код. Поэтому редкие сбои между выкаткой агента и его отчётом могут не засчитаться.

### 7. Сроки и кто правит

- Взять случай — 5 минут (`acceptTimeoutMs`). Сделать — до 60 минут (`workTimeoutMs`).
- Мост не ответил за 3 секунды при передаче — врач лечит сам. В отчётах пометка «Paseo недоступен».
- Пока агент работает, врач раз в 30 секунд смотрит, нет ли итога, и проверяет мост. Мост молчит 5 минут подряд (`bridgeSilenceMs`) — врач забирает случай. Короткий перерыв — перезагрузка моста, сон Mac — случай не отнимает.
- Не взял, не уложился, не смог, мост пропал — отчёт `reclaimed`. Врач отменяет задачу у моста и лечит сам.
- Мост не подтвердил отмену — врач повторяет её на каждом своём шаге. Лечит дальше, но свою правку не выкатывает, пока мост не подтвердит отмену или не пройдёт срок работы агента. Так даже без моста правит и выкатывает один.
- Правит один. После `reclaimed` «взял» агента получает отказ. Его итог врач только записывает, своё не переделывает. Исключение — поздняя выкатка агента. Работающую версию никто, кроме агента, уже не вернёт, поэтому врач берёт её под наблюдение в том же случае. Своё лечение врач при этом бросает, если ещё не выкатил.

### 8. Проверка целиком

1. На Mac: `paseo plugin ls` — мост `running`.
2. С сервера: `nc -vz <адрес Mac в tailnet> 7710` проходит. С Mac: `nc -vz <адрес сервера в tailnet> 7810` проходит.
3. Тестовый сбой в приложении. В Telegram и у агента — отчёт «передал случай агенту Paseo». Агент отвечает `accept`, затем `done` или `cannot`. Врач закрывает случай или забирает его.
4. Выключите Paseo и повторите сбой. Врач лечит сам, в отчёте — «Paseo недоступен».
