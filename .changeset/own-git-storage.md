- **Своё хранилище на сервере вместо GitHub.** origin врача может быть bare-репозиторием на том же сервере под пользователем git с git-shell. Врач ходит по SSH своим ключом: `REMONTNIK_GIT_SSH_KEY` (текст ключа, с `\n` или base64) и обязательная с ним `REMONTNIK_GIT_KNOWN_HOSTS`. Токен не нужен. Ключ живёт только в окружении врача и во временной папке контейнера (права `0600`). Хранилище держат `receive.denyNonFastForwards`, `receive.denyDeletes` и хук `deploy/git-update-hook`: метки `remontnik/**` не двигаются и не удаляются, а ключ врача (принудительная команда `deploy/git-shell-remontnik-doctor`) пишет только в основную ветку и `remontnik/**`. Хук и config принадлежат root. Рецепт — `docs/security.md`, «Своё хранилище на сервере».
- **check-config для своего хранилища.** Для origin `ssh://…` вместо правил GitHub проверяет по SSH ключ и ключ сервера, настройки хранилища, хук, роль ключа врача и что пользователь git не пишет в config и хуки. Пробы ничего не записывают. Что хук и config принадлежат root, по SSH не проверить: всегда предупреждение с командой для root. С GitHub всё как раньше.
- **Образ и compose врача.** В образе есть `openssh-client`, у контейнера врача — `extra_hosts: host.docker.internal:host-gateway`: так он доходит до SSH сервера.

### Как обновить приложение

С GitHub:

1. На сервере перевести клон Ремонтника на метку новой версии и пересобрать врача (`docker compose -f deploy/compose.remontnik.yml up -d --build`). Настройку и окружение не менять.

Чтобы перейти на своё хранилище:

1. Обновить врача, как выше.
2. root на сервере делает хранилище, пользователя git и ключи по рецепту `docs/security.md`, «Своё хранилище на сервере»: хук и принудительная команда — из `deploy/` новой версии.
3. Человек отправляет в хранилище код со своего компьютера: `git push` своим ключом.
4. Закрытый ключ врача — в окружение врача `REMONTNIK_GIT_SSH_KEY` через `secret-handoff`, строка ключа сервера — в `REMONTNIK_GIT_KNOWN_HOSTS`. `REMONTNIK_GIT_TOKEN` убрать.
5. `REMONTNIK_APP_DIR` заменить клоном хранилища (`git clone --no-local`, origin `ssh://git@host.docker.internal/<путь>.git`, владелец `10001:10001`). `REMONTNIK_UID` оставить `10001`. Межсетевой экран сервера должен пускать SSH из подсетей Docker.
6. Перезапустить врача и проверить внутри его контейнера: `remontnik-doctor check-config` — ошибок нет, одно предупреждение про владельца хука; выполнить его команду от root.
