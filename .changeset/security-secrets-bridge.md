Закрыты находки проверки безопасности.

- `core`, `doctor`: полная память повторов отказывает (`503 replay_memory_full`), а не вытесняет старые метки; метку команды управления занимает только запрос, прошедший проверку роли; на `/v1/control/*` — не больше 60 чужих запросов в минуту с адреса (`429`); команды владельца предел не тратят; `signRequest` ставит ещё подпись заголовков без тела (`X-Remontnik-Head-Signature`, проверка — `verifyRequestHead`): по ней врач читает тело команды владельца мимо общих мест; чужие тела там читаются не больше 8 одновременно с адреса и 128 всего, лишнее вытесняет самое старое недочитанное чтение старше 2 секунд (вытеснить некого — `503 body_reads_full`), отказ без чтения тела освобождает место сразу.
- `doctor`: общий секрет, секрет владельца и секрет моста — попарно разные и не короче 32 знаков; проверяют `check-config` и старт врача.
- `paseo-bridge`: агент подписывает команды ключом задачи из письма, секрет моста ему не нужен. **Ломающее:** `remontnik-paseo` требует ключ — `REMONTNIK_PASEO_KEY` или `--key`. Ключ гаснет через 15 минут после итога (повтор итога до того — 409), через 24 часа после отмены и при новой задаче случая; у путей агента своя память повторов с квотой на ключ. Тип отчёта — внутри блока данных. Заголовки проверяются до тела, есть пределы соединений и время на заголовки.
- `browser`: пока в контексте есть страница с вписанным паролем, соединения с адресами вне `allowedOrigins` закрыты во всём контексте (`refused_leak`) до настоящего нового документа (не после `204`, `stop()`, скачивания и history API). Решает прокси службы, через который идёт весь трафик Chromium: его не обходят ни `SharedWorker`, ни WebRTC, ни WebTransport; UDP мимо прокси закрыт флагами, имена хостов разрешает прокси; внутренние адреса (петля, частные сети, метаданные облака, IPv4 внутри IPv6) вне `allowedOrigins` прокси не пускает и без пароля (`refused_internal`), проверяя адрес после DNS и соединяясь на него же; прокси требует имя и пароль, свои на каждый запуск (`407`); одинаковые отказы сливаются, их число ограничено; живой экран принимает `POST` только со своей страницы, за прокси с TLS — и `https://<хост>`.
