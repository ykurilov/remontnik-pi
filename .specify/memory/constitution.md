# Конституция «Ремонтника Pi»

Правила, которые проверяет каждый план и каждая задача. Источник — решения Юрия при запуске проекта (2026-10-26) и его общие правила разработки.

## Основные принципы

### I. Открытый репозиторий без секретов

Репозиторий открытый: им делятся с учениками. В коде, примерах, тестах, документации и истории git НЕЛЬЗЯ хранить ключи, токены, адреса серверов, домены приложений, данные пользователей и выдержки из настоящих разговоров. Настройки приходят только из окружения или из файла настроек приложения вне репозитория. Тестовые данные — выдуманные. Перед каждым выпуском автоматическая проверка ищет секреты во всём дереве и в истории.

### II. Безопасность выкатки важнее скорости

Врач выкатывает правку сам только при зелёных тестах и зелёных затронутых сценариях eval. Перед выкаткой — метка git прежней рабочей версии и сохранённая на сервере прежняя собранная версия. После выкатки — наблюдение и самостоятельный откат при ухудшении. Неуверенность = не выкатывать, а сообщить.

### III. Запретные зоны неприкосновенны

Врач НИКОГДА не выкатывает правки, которые касаются схемы базы, денег и оплаты, доступов и ключей, кода Agent Chat SDK (`@ykurilov/agent-chat-*`). Такое он только описывает и сообщает. Проверка запретных зон — кодом по списку путей и признаков, а не решением модели.

### IV. История неприкосновенна

Каждая правка врача — отдельный коммит с понятным сообщением в своей ветке. Врачу разрешены только свои ветки и метки. Переписывать историю и force-push в основную ветку НЕЛЬЗЯ — это ограничено правами доступа, а не только кодом.

### V. Без бесконечных циклов и лишних трат

Защита от циклов «правка → откат → правка» и потолки расходов на модель и eval обязательны и проверяются тестами. Промпты строятся так, чтобы неизменная часть шла первой и попадала в кэш модели.

### VI. Работает без Paseo и главного агента

Сторож и врач работают на сервере сами. Paseo и главный агент приложения — только дополнительный получатель отчётов, когда доступны. Telegram-отчёт уходит всегда.

### VII. Глубокие модули, тонкие интерфейсы

Набор пакетов `@ykurilov/remontnik-*`. Каждый пакет делает одно дело и даёт маленький интерфейс. Приложение подключает набор по инструкции, как Agent Chat SDK. Названия файлов, функций и переменных — предметные.

### VIII. Сначала тесты

Новый модуль — по TDD: тест, убедиться, что он красный по нужной причине, затем код. Модели в тестах подменяются; живые вызовы — отдельная группа.

## Технические ограничения

- TypeScript, Node 22, pnpm, один файл-замок, монорепозиторий пакетов.
- Модель сторожа и врача: DeepSeek 4.1 Flash. Основной путь — DeepSeek API, запасной — OpenRouter `deepseek/deepseek-v4.1-flash-1017`.
- `@earendil-works/pi-durable` — экспериментальный: версия закреплена точно, автообновление выключено.
- Пакеты выходят одной версией через changesets, журнал пишется для агента, который обновляет приложение, с разделом «Как обновить приложение».

## Порядок работы

- Код Ремонтника правит только агент-хозяин набора. Приложения присылают ему задачи.
- Полный цикл спецификация → план → задачи — для новой возможности или правки нескольких пакетов.
- Прогоны тестов и сборок — на iMac.
- Коммит после каждого законченного этапа.

## Управление

Конституция главнее остальных договорённостей в репозитории. Меняется только по решению Юрия: правка этого файла, новая версия (MAJOR — убран или переопределён принцип, MINOR — добавлен, PATCH — уточнение формулировок), запись даты. Каждый план содержит раздел «Проверка конституции».
