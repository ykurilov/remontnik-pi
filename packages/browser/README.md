# @ykurilov/remontnik-browser

Свой браузер врача Ремонтника: снимки страниц с номерами элементов, действия, сохранённые входы, живой экран владельца. Основа — `playwright-core` (точная версия) и Chromium. Пароль никогда не попадает к модели: ни в снимок, ни в ответ, ни в журнал.

## Запуск

```sh
remontnik-browser serve
```

Окружение:

| Переменная | Что это |
|---|---|
| `REMONTNIK_BROWSER_TOKEN` | ключ врача, не короче 16 знаков |
| `REMONTNIK_BROWSER_VAULT_KEY` | ключ хранилища входов: 32 байта в base64 |
| `REMONTNIK_BROWSER_DATA_DIR` | профили, входы (`logins.json`), снимки экрана |
| `REMONTNIK_BROWSER_POLICY` | путь к JSON: `allowedOrigins`, `allowedMutations`, `profiles` |
| `REMONTNIK_BROWSER_LISTEN` | адрес службы, по умолчанию `127.0.0.1:7700`; «все адреса» — только явно (в образе — `0.0.0.0:7700`) |
| `REMONTNIK_BROWSER_LIVE_LISTEN` | адрес живого экрана, только частная сеть; не задан — живого экрана нет |
| `REMONTNIK_BROWSER_OWNER_TOKEN` | ключ владельца, не совпадает с ключом врача |
| `REMONTNIK_BROWSER_URL` | для консольных команд: адрес службы, по умолчанию `http://127.0.0.1:7700` |

Политика:

```json
{
  "allowedOrigins": ["https://app.example.com"],
  "allowedMutations": [{ "method": "POST", "pathPattern": "/api/chat" }],
  "profiles": [{ "name": "remontnik", "viewport": { "width": 1280, "height": 800 } }]
}
```

В `pathPattern` знак `*` — один кусок пути, `**` — весь остаток. Прокси задаётся в профиле (`proxy.server`, имя и пароль — через имена переменных `usernameEnv`, `passwordEnv`).

Образ: `deploy/browser.Dockerfile`. Порт службы публикуйте только во внутреннюю сеть compose или на частный адрес, не на все адреса хоста.

## HTTP

`POST /v1/<команда>`, заголовок `Authorization: Bearer <ключ врача>`, тело — JSON. `GET /health` — без ключа.

| Команда | Вход | Успех |
|---|---|---|
| `open` | `{ profile }` | `{ ok }` — запускает профиль |
| `read`, `back` | `{ profile }` | `{ ok, url, title, snapshot }` |
| `url` | `{ profile, url }` | то же |
| `click` | `{ profile, ref, danger }` | то же |
| `type` | `{ profile, ref, text, submit?, danger }` | то же |
| `key` | `{ profile, key }` | то же |
| `scroll` | `{ profile, direction, px? }` | то же |
| `shot` | `{ profile }` | `{ ok, path }` — JPEG, поля пароля под маской |
| `logins` | `{ site? }` | `{ ok, logins: [{ id, site, login, profile }] }` |
| `fill-password` | `{ profile, entryId, ref }` | снимок |
| `status` | `{ profile }` | `{ ok, state: ready \| busy \| needs_human, reason? }` |

Отказ — `{ ok: false, code, message }`:

| `code` | Когда |
|---|---|
| `refused_origin` | сайт вне `allowedOrigins`; элемент во фрейме чужого сайта; вход из хранилища от другого сайта |
| `refused_danger` | `danger` = `send`, `pay`, `delete`, `publish`, или цель сама похожа на опасное действие |
| `refused_mutation` | изменяющий запрос вне `allowedMutations` (в `message` — метод и путь) |
| `refused_field` | `fill-password` не в поле пароля |
| `refused_profile` | вход из хранилища от другого профиля |
| `refused_human_control` | управление у владельца |
| `needs_human` | капча или запрос одноразового кода; пока человек её не прошёл — любая страничная команда, кроме `read` и `shot` |
| `not_found` | нет профиля, номера элемента или входа |
| `bad_request` | неверный вход, например нет `danger` |
| `timeout` | страница не ответила вовремя |

HTTP-коды: неверный ключ — 401; больше 10 неверных ключей за минуту с одного адреса — 429 с `code: too_many_attempts`; неизвестная команда — 404; тело не объект — 400; сбой службы — 500 с `code: internal`.

## Консоль

```sh
remontnik-browser read -p remontnik
remontnik-browser click -p remontnik --ref e12 --danger none
remontnik-browser logins add --site https://app.example.com --login demo@example.com --profile remontnik --password-stdin
remontnik-browser logins list
remontnik-browser logins remove 3
```

Добавить и удалить вход можно только в консоли на сервере браузера. Пароль читается только из стандартного ввода; `--password` отклоняется.

## Живой экран

`GET /live?profile=<профиль>` на `REMONTNIK_BROWSER_LIVE_LISTEN`. Вход по ключу владельца, куки `HttpOnly`, `SameSite=Strict`. Не больше 5 неверных ключей в минуту с одного адреса: чужие ошибки из той же сети владельцу вход не закрывают.

У куки нет флага `Secure`: живой экран работает по обычному HTTP. Открывайте его только по частному шифрованному каналу (например, Tailscale) или за прокси с TLS. `POST` живой экран принимает только со своей страницы: чужой или пустой (`null`) `Origin` — `403`.

Пока на странице вписан пароль, браузер закрывает любые запросы на сайты вне `allowedOrigins` (`refused_leak`), в том числе WebSocket. На новой странице замок снимается. Остатки риска — `docs/security.md`, «Пароли браузера».

«Взять управление» и «Вернуть» идут тем же потоком, что и ввод, поэтому «Вернуть» не обгоняет набранный текст. Когда владелец нажал «Вернуть», найденная до этого капча или запрос кода считаются пройденными. Кадры идут по `WS /live/stream`, ввод владельца доходит, только пока он взял управление. Пока управление у владельца, врач получает `refused_human_control`. Нет связи с владельцем 2 минуты — управление возвращается врачу. Замки сайтов и запросов действуют и при ручном управлении.

## Что служба перепроверяет сама

Модель могут сбить текстом страницы, поэтому то, что она заявляет, служба проверяет сама. При сомнении — отказ.

- **Опасные действия.** Перед `click`, `type` с `submit` и `key` Enter или Space служба смотрит на саму цель: подпись, текст, адрес ссылки или формы. Для отправки формы — её кнопки отправки, для клавиши — элемент в фокусе. Оплата, удаление, публикация, отправка сообщения людям (по-русски и по-английски) отклоняются, что бы ни было указано в `danger`. Обычное «Отправить» не опасно: так уходит форма или сообщение боту.
- **Капча и коды.** После `needs_human` врачу доступны только `read` и `shot`, пока владелец не вернёт управление с живого экрана или новый `read` уже не увидит проверки.
- **Фреймы.** Фрейм тоже грузится только с `allowedOrigins`; пустой фрейм наследует сайт родителя. Фрейм чужого сайта в снимке — только пометка `[фрейм=скрыт: сайт вне allowedOrigins]`, его элементы действий не принимают.
- **Сайт входа.** `fill-password` вписывает только в точный origin входа, без поддоменов, и только по `https:`. Исключение — `localhost` и `127.0.0.1` для проверок.

Чего сетевой замок не ловит: запрос `GET` с побочным действием на сайте и любой запрос, подходящий под слишком широкий шаблон `allowedMutations` (например, `/**`). Шаблоны держите узкими.

## Решение T092: номера элементов

Закреплённая `playwright-core` 1.64.1 сама даёт снимок с номерами: `page.ariaSnapshot({ mode: 'ai' })` выдаёт `[ref=e12]`, а `page.getByRef('e12')` находит элемент. Номер того же элемента не меняется между снимками. Внутри фреймов номера вида `f1e2`.

Берём встроенные номера и дерево (`ariaSnapshotJSON`), а текст снимка собираем сами. Причина: встроенный текст показывает значение поля пароля открыто и не отличает поле пароля от обычного поля. Свой обход DOM с `data-remontnik-ref` не нужен: он менял бы страницу и повторял готовое.

Как скрываем пароль:

- Поле с `type=password` или `autocomplete=current-password`/`new-password` помечается «[поле пароля]» и остаётся помеченным, даже если страница сменит тип поля (кнопка «глаз»).
- Поле, куда служба вписала пароль, помечается «[пароль вписан]» навсегда.
- Поле, значение которого содержит сохранённый пароль, тоже помечается «[пароль вписан]» и закрывается маской. Так скрыто и поле, которое сайт пересоздал после вписывания (перерисовка при «показать пароль»).
- Значения таких полей в снимке — «[скрыто]», на снимке экрана — под маской.
- Последняя страховка — фильтр выхода. Он вырезает все сохранённые пароли из ответов и журналов: как есть, со схлопнутыми пробелами, в JSON, в HTML, в `%xx`-кодировании любого регистра, в hex и в base64. Если фильтр сломался, текст не выводится вовсе. От преобразований самой страницей (перевёрнутый пароль, часть пароля, своё шифрование) фильтр не защищает.
- Пароль короче 8 знаков не сохраняется: его нельзя надёжно вырезать из текста.

## Замки паролей

1. Каждый вход шифруется AES-256-GCM; сайт, профиль и логин входят в проверку подлинности.
2. Пароль попадает в хранилище только из стандартного ввода и не короче 8 знаков.
3. `fill-password` вписывает только в поле пароля и только на точном сайте входа по `https:`, в том числе внутри фрейма.
4. Команды выполнения своего кода на странице нет.
5. Снимок скрывает значения.
6. Снимок экрана закрывает поля маской.
7. Фильтр выхода вырезает пароли из всего, что уходит наружу.
